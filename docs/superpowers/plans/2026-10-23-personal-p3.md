# Personal P3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** entregar volume semanal, modelos privados/globais e periodização na ficha atual do Personal.

**Architecture:** evolução aditiva do fluxo de rascunhos/finalização, sem segundo caminho de ativação. Regras puras na API e web, com vetores de paridade; snapshots calculados no servidor e tabela própria de modelos sob RLS.

**Tech Stack:** NestJS 11, Prisma 7/PostgreSQL, Next.js 16/React 19, TanStack Query, Jest/Vitest/Cypress.

**Spec:** `docs/superpowers/specs/2026-10-23-personal-p3-design.md`, aprovada em 23/10/2026.

**Estado:** tarefas 1–7 concluídas localmente em 24/10/2026. [Relatório final](../../runbooks/personal-p3-verification.md): API 755, web 748, PostgreSQL/HTTP/RLS 253, nove verificações reais de navegador; revisão final aprovada após correções. Execução nativa Cypress limitada pelo bloqueio de download; cenários versionados e jornada executada com Chromium/Playwright.

## Global Constraints

- Sessão PERSONAL; contexto `safemove_clinical`; filtros por dono e Client; no-store.
- Rascunhos V1/V2 legíveis, novas escritas V3, limite 64 KiB e `expectedVersion` preservados.
- Frequência 1–7; séries reconhecidas somente como inteiro 1–100; secundários com peso 0/0,5/1.
- Periodização opcional 4–12 semanas; sem ela duração legada 1–104; datas civis/fuso IANA.
- Modelos imutáveis; globais somente leitura; importação cria rascunho sem ativar treino.
- Sem produção, deploy, push, novo portal ou automação de carga.

## Review Focus

- Valores antigos ausentes devem permanecer desconhecidos; copiar/salvar não deve inventar frequência.
- Importação concorrente/retry deve preservar OPEN e ficha ativa, inclusive após timeout.
- Troca de conta durante modal/request deve invalidar dados privados e resultados tardios.
- Texto complexo em séries/repetições/esforço deve sobreviver sem conversão numérica parcial.
- Virada de semana no fuso do plano e impressão de semana escolhida devem concordar com a API.
